# Security policy

## Reporting a vulnerability

Please do not publish suspected vulnerability details, proof-of-concept exploit code, or sensitive data in a public issue or pull request.

When GitHub private vulnerability reporting is enabled for this repository, use the repository's **Security** tab and choose **Report a vulnerability** to submit a private report. Availability is controlled by repository settings and is not guaranteed.

If private vulnerability reporting is unavailable, use the maintainer's public GitHub profile, [@medo-iq](https://github.com/medo-iq), to request a private reporting route. Avoid posting exploitable details publicly while seeking that route. Do not send credentials or unrelated personal information.

Include, when safe and relevant:

- The affected revision or commit and environment.
- A concise description of the security impact.
- Steps to reproduce or a minimal proof of concept, shared privately.
- Any mitigations or workarounds you have identified.

## Supported versions

CemuX is an early-stage project and does not currently publish a formal version support matrix or maintenance window. The current default branch is the primary review target. Reports concerning other revisions may be assessed case by case; no backport or response-time commitment is implied.

## Review expectations

Maintainers should reproduce and assess a report before describing a vulnerability as confirmed. Changes should be narrowly scoped, tested, and reviewed for related regressions. Security review is not a substitute for a formal security audit, and no audit or certification is claimed for this project.
